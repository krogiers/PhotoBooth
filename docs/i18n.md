# Guest-facing text (i18n)

## The need

Every string a guest sees — the kiosk idle/countdown/result screens and the
small web pages their phone opens — has to be translatable and tweakable
without a rebuild, the same way `config/photobooth.properties` and
`config/overlay.png` are.

## How it works — [`Strings`](../src/main/kotlin/com/photobooth/i18n/Strings.kt)

Text lives in `.properties` files, never hardcoded in Kotlin.
`Strings.load(languageCode)` (from `ui.language`, default `en`) merges up to
three layers, later ones winning:

1. **English fallback** — `src/main/resources/i18n/en.properties`, bundled in
   the jar. Always loaded, so a missing key anywhere else degrades to
   English rather than crashing the kiosk.
2. **Bundled language** — `src/main/resources/i18n/<code>.properties` if it
   exists. Built in: `en`, `nl`.
3. **Config override** — `config/i18n/<code>.properties` if it exists,
   layered on top.

Look up a string with `strings.t("key")`, or `strings.t("key", arg, …)` for
one with `%s` placeholders (`String.format` semantics).

A few keys hold a **list** — a comma-separated value read with
`strings.list("key")`. `smile_words` is the shout the kiosk shows when the
shutter fires; one is picked at random per shoot. Manage the set per event by
editing that one line in `config/i18n/<lang>.properties`, e.g.
`smile_words=Lachen!,Kaas!,Spaghetti!,Whisky!,Komijn!`.

`ui.language` with no bundled translation *and* no override file is a hard
error — it won't silently fall back to English for the whole app.

## Adding or changing text

- **Reword a few strings** in a built-in language: create
  `config/i18n/<code>.properties` with just the keys you want to change.
- **Add a whole new language** that isn't built in: same file, but you'll
  want every key. See
  [`en.properties`](../src/main/resources/i18n/en.properties) for the full
  list.
- **Change the defaults in the repo**: edit both
  [`en.properties`](../src/main/resources/i18n/en.properties) and
  [`nl.properties`](../src/main/resources/i18n/nl.properties). `StringsTest`
  guards that every bundled language has every key — keep its `keys` list in
  sync when you add or remove one.

None of these need a rebuild except editing the bundled defaults.
